# 数据层同步就绪改造 — 本地优先 + WebDAV/云盘标准包

## Goal

把数据层设计成"同步就绪"：SQLite 唯一本地真源 + 版本化标准包交换格式 + 本地优先（local-first）增量同步。先落地 WebDAV/云盘备份（备份即同步），后续按阶段扩展到多端自动同步，为标签特色提供跨端一致的基座。**本任务为规划任务，默认不实施；每个阶段开工前单独确认并拆子任务。**

## Background（背景与已确认决策）

- 现状混乱根源：JSON（早期方式）与 SQLite（后来引入）双写双读，两个数据源互相缺数据。长期方向是把 JSON 降级为"只导出不读"，SQLite 成为唯一真源。
- 标签是应用特色：标签按名字做 ID（`name.trim().toLowerCase()`，Dart/Rust 已对齐），跨端天然稳定，同步难度低。
- 同步真正的难点：**书标识**（当前 key = `来源类型|来源ID|路径`，本地书跨设备路径必然不同，需内容级稳定 ID，路径降级为别名）和**删除/冲突**（需 updated_at + 墓碑）。
- 已确认方向：**本地优先（local-first）+ WebDAV/云盘标准包**。冲突按实体 LWW（updated_at 最新者胜）+ 墓碑；标签重命名 = 删除旧名 + 新建新名（墓碑保证传播）。
- 前置依赖：`08-01-fix-tag-persistence` 先落地真源收敛 + 一次性对账，本任务在其基础上做 schema/格式/同步层，不重复改持久化链路。

## Requirements（按阶段规划，非一次性实施）

- **P0 同步元数据落库**（依赖 fix-tag-persistence 完成后）：tags / book_tags / records / metas / settings 增加 `updated_at`、`deleted`（墓碑）；新增 `device_id` 与同步游标表；书表增加稳定 ID 列（内容 hash 或内嵌 UUID，方案待定 O-BI）。
- **P1 标准包格式**：版本化交换格式（manifest + 按实体分块的增量 + 墓碑 + schema 版本），本地备份、云备份、设备间同步共用；替代当前 library.json 的读写角色；导出/导入往返无损（round-trip）。
- **P2 备份即同步（阶段 A）**：标准包上传到用户自有 WebDAV/云盘（应用已有 WebDAV 基建，如坚果云），支持手动/定时备份与恢复。
- **P3 增量同步（阶段 B）**：设备 A 推自上次游标以来的 delta，设备 B 拉取并按 LWW + 墓碑合并；需要处理多设备时钟与离线编辑。
- **P4 可选扩展（阶段 C）**：自建/第三方后端 + 账号体系 + 实时推送；仅当出现多端同时离线编辑需求再评估 CRDT（Automerge/Yjs 等）。

## Acceptance Criteria（规划任务不执行，以下为各阶段开工时的验收锚点）

- [ ] P0：SQLite 表含同步元数据且现有读写不受影响（回归通过）
- [ ] P1：标准包导出→导入后数据与标签关联无损；schema 版本不兼容时可拒绝/提示
- [ ] P2：WebDAV/云盘上传/下载/恢复全链路可用；失败可观测、可重试
- [ ] P3：两端各自离线编辑后合并不丢标签、不复活已删项（墓碑生效）
- [ ] P4：仅在需求确认后评估，默认不进入范围

## Open Questions（各阶段开工前确认）

- **O-BI** 书稳定 ID 方案：内容 hash（无侵入、同内容同 ID）还是漫画包内嵌 UUID（需写回文件/ComicInfo.xml，跨设备一致但依赖文件可写）——推荐内容 hash + 可选的显式 UUID 覆盖
- **O-SYNC** 同步粒度与范围：是否同步设置/书源/阅读进度，还是仅标签（本任务默认全量实体，标签优先）
- **O-CLOUD** WebDAV 目录约定与冲突命名（如 `RCH/sync/latest.rchpkg` + 时间戳归档）
- **O-UI** 备份/同步入口与状态展示（设置页 vs 新页面）——规划期默认设置页
