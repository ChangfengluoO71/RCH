# 云端阅读与海报墙请求治理：技术设计

## 产品合同

- “云端封面加载”作为全局设置持久化，默认 `true`。旧设置缺失该字段时迁移为 `true`。
- 开启时，当前视口内的未缓存云端漫画可以尝试取得封面；关闭时不发起新的远程封面请求。
- 无论开关如何，内存缓存、封面磁盘缓存与 raw 本地缓存都应优先可用；关闭开关不能把已缓存封面变回占位图。
- 封面尝试只能读取经实际响应验证可局部访问的远程内容：只有 `206 + 有效 Content-Range` 才是成功。Range/随机访问不可用时，海报墙保留既有占位并在同书源本次浏览会话提示一次，绝不下载整本漫画。
- 自定义封面是用户明确发起的操作：先走本地缓存和安全的局部读取。Range 不可用时显示确认框，只有用户确认后才下载整本；不能直接复用会静默走 `auto`/整本下载的打开策略。

## 现状缺口

`ComicCover` 目前以 raw 缓存是否存在决定是否调用封面 API；放开该守卫后，百度、115、夸克及 115 Cookie 的 `*_cover` 会在 Range 不可用时调用 `download_to_raw_cache`。此外，封面缓存目前有时用 raw 本地路径、有时用远程路径计算 key，raw 缓存清理后会失去对同一封面磁盘缓存的命中。

阅读器的当前页、预取和封面也没有共同请求预算：`Reader` 会为预取直接起线程，`_CoverLoadQueue` 仅有全局 FIFO 的 4 并发，无法保证当前页优先。

## 分层方案

```text
AppSettings.remoteCoverFetchEnabled (默认 true)
           |
ComicCover / 可见卡片生命周期
  内存缓存 -> 稳定磁盘缓存 -> CoverRequestScheduler
                                  |
                         CoverFetchPolicy
                          cacheOnly | remotePartialOnly
                                  |
                         Rust source cover APIs
              缓存键规范化 + Range/随机访问校验 + typed outcome
                                  |
      RequestGovernor：前台当前页 > 阅读预取 > 海报墙封面
```

### 1. 协议判定、稳定封面身份与缓存

`Accept-Ranges` 仅作为优化提示，不能当作能力保证。每个远程资源首次需要远程封面时以最小连续 Range 进行探测；只接受状态 `206` 且 `Content-Range` 可解析、与所请求区间/总长度一致的响应。任何 `200`、`416`、缺失或不匹配的响应均在读取 body 前丢弃，并归类为 `rangeUnavailable`，不会进入整本下载路径。

按“书源范围 + 资源逻辑路径 + 内容版本”缓存这一能力结果：目录条目的 size/mtime 可用时参与版本；缺少版本信息时使用短 TTL。`rangeUnavailable` 也是负能力缓存，直到目录刷新、版本变化或 TTL 到期才重新探测，防止每个可见卡片重复探测。`If-Range` 不用于海报墙探测，因为验证器不匹配时协议允许服务端返回整个表示。

封面磁盘缓存使用稳定的逻辑身份：书源类型、非敏感书源标识/源范围、远程逻辑路径、封面页、尺寸和裁剪。不得使用会随 raw 缓存存在与否变化的本地文件路径，也不得将密码、Cookie 或下载直链写进缓存键。读、写和按书清理必须使用同一身份。

新增显式的 `cacheOnly` 读取路径：它只查询内存、封面缓存和 raw 本地文件，不执行会话、downlink、metadata 或 Range 请求。这样关闭开关时仍能显示已缓存封面，同时可在测试中证明“零新增网络请求”。

### 2. 可见封面调度器与提示聚合

将 `_CoverLoadQueue` 演进为按稳定封面身份共享 Future 的调度器：

- 同一书源、资源和封面规格同时只执行一次；多个卡片订阅同一结果。
- 仅已进入可见渲染窗口的卡片入队；离开窗口的等待任务取消。已进入 FFI 的任务无法强杀，但其结果不能回写已销毁的卡片。
- 队列同时维护总并发和按书源并发；具体阈值由基线结果决定，不在没有实测前硬编码。
- 对认证失效、429、超时、Range 不支持分别分类，应用有界退避；不因 rebuild 或滚动立即重试。

海报墙的 `rangeUnavailable` 卡片使用已有占位。浏览容器聚合同一书源的首次失败，显示一次非阻塞提示（例如可关闭的顶部提示/提示条），说明“该书源当前不支持流式封面；可打开漫画或在自定义封面中选择下载整本”，避免每张卡片重复 Snackbar。

### 3. Rust 远程读取策略

通过显式 `CoverFetchPolicy`（或等价的类型化参数）贯穿 WebDAV、SFTP、百度、115、115 Cookie、夸克封面 API：

- `cacheOnly`：只能本地命中，否则返回未命中。
- `remotePartialOnly`：可获取必要元数据并读取 Range/SFTP 随机块；一旦服务端不支持局部读取，返回 `rangeUnsupported` 类结果，不得调用 `download_to_raw_cache`。

自定义封面不调用普通 `open_*_book(strategy: auto)`。新增“缓存优先、仅局部读取”的打开/封面编辑路径，返回 `NeedsWholeBookDownload { size? }`；Flutter 展示下载确认后，才显式调用既有 `download` 路径并展示进度。

为阅读器和封面引入以书源范围为键的**自定义阻塞优先级预算**。它不是 FIFO `Semaphore`：当前页、预取、封面各有队列，并为当前页保留至少一个许可；同级 FIFO，低优先级采用有限老化以避免永久饥饿。预算在一次“读取当前页 / 预取页 / 生成封面”操作开始时获得许可，且不抢占已开始的阻塞 I/O。`Reader` 的预取线程改为受该预算控制，避免六个预取线程在慢网盘上长期压住前台操作。

MVP 只取消尚未开始的任务并丢弃离屏订阅者的结果。现有同步 `spawn_blocking` I/O 已启动后无法可靠中断；把全部提供方重写为可合作取消的异步客户端另立性能任务，并以本次基线决定是否值得投入。

### 4. 可观测性和隐私

测试和可选调试统计只记录来源类别、请求类别、缓存命中、取消、退避和耗时桶；不记录凭据、完整 URL 或真实漫画路径。基线和实现后使用同一 fake provider 场景，并以真实账号手工冒烟补充协议差异。

## 兼容性、发布与回滚

- 旧设置自动保持默认开启；用户可随时关闭开关止住新封面网络请求。
- 不改变用户点击打开漫画时的 `BookOpenStrategy`，也不新增网盘提供方。
- 若某书源协议异常，返回占位图并按退避处理，而非全局关闭其他书源。
- 紧急回滚时关闭设置入口/恢复 cache-only 行为；已有封面缓存和阅读缓存不受影响。
