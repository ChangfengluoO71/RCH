# 同步完善（全量导出 / 设备包 / 自动同步 / 设备列表）+ 文件夹封面

## Goal

1. 完善 WebDAV/目录同步：全量导出、云端按设备保留同步包、自动同步、已同步设备列表、增量包缺失提示。
2. 文件夹封面：文件夹封面取“文件夹内第一个漫画文件”的封面；无漫画文件的文件夹无封面；网盘文件未下载时显示“未缓存”，下载后显示封面。

## Constraints

- 封面检测全走本地：文件夹封面的“判定 + 图片生成”全程只读本地数据（目录快照 / 阅读记录 / raw 缓存），**绝不触发网盘服务器请求**（list / downurl / probe / 下载等一概不调用）。
- 教训来源：2026-08-08 会话中 M2 文件夹封面检测曾对每个子目录重复发起 list，配合目录/文件双请求导致打开根目录 10+ 次请求，触发 115 阿里云 WAF IP 封禁（HTTP 405）。本次方案必须以“0 新增请求”为验收底线。
- 网盘请求只允许发生在用户主动浏览 / 打开 / 下载 / 刷新时，且不因封面展示而额外发起。

## Requirements

- A1 全量推送：同步面板提供「全量推送」，导出忽略增量游标（`incremental=false`），保证老书源（如百度）也能进入包。
- A2 云端按设备保留：推送写入 `devices/{deviceId}/latest.rchpkg` + `devices/{deviceId}/meta.json`（deviceId / deviceName / lastPushAt），并继续写根 `latest.rchpkg` 兼容旧版本；拉取合并根包与所有设备包，避免互相覆盖丢数据。
- A3 增量缺失提示：首次接触某设备的增量包时提示“该设备推送的是增量包，可能缺少历史书源，建议对方做一次全量推送”。
- A4 自动同步：设置同步间隔（关闭 / 15 / 30 / 60 / 180 分钟），应用运行期间定时执行“先拉后推”，启动后延迟执行一次，busy 时跳过。
- A5 设备列表：同步面板展示已同步设备（名称、短 ID、最近同步时间），数据来自本地 devices 表 + 云端 `devices/` 目录。
- B1 本地文件夹封面：有显式 cover.jpg 用 cover.jpg，否则用文件夹内第一个漫画文件封面；无漫画文件 → 无封面。本地“漫画文件”= 图片（文件夹式漫画书）或漫画压缩包（容器文件夹）。
- B2 网盘文件夹封面（WebDAV / SFTP / 百度 / 115 / 夸克）：封面检测只读本地数据，**零网盘请求**。本地快照/阅读记录表明子目录含漫画文件 → 封面 = 第一个漫画文件（复用 ComicCover；首文件未下载自动显示“未缓存”）；本地无该子目录数据 → 与漫画文件一致显示“未缓存”占位，点击正常下钻浏览；本地数据表明无漫画文件 → 普通文件夹卡片（无封面）。
- B3 网盘文件未下载显示“未缓存”，下载完成后自动变为封面（无需手动刷新或重新拉取列表）。

## Acceptance Criteria

- [ ] 「全量推送」可用，导出的包包含全部书源（含未变更的老书源）。
- [ ] 云端出现 `devices/{deviceId}/` 结构；两台设备互推互拉不互相覆盖、不丢书源。
- [ ] 拉取后同步面板列出已同步设备及最近同步时间。
- [ ] 自动同步按设定间隔执行（先拉后推），忙时不重入。
- [ ] 首次拉取对方增量包时给出“建议全量推送”提示。
- [ ] 网盘模式下打开目录、滚动海报墙，封面检测不产生任何新增网盘请求（0 请求；回归用请求计数或断网验证）。
- [ ] 本地与网盘漫画文件夹显示第一个漫画文件封面；网盘未下载或本地无数据时显示“未缓存”，下载/浏览后自动变为封面或普通文件夹卡片（无需手动刷新）。
- [ ] 本地无数据的网盘子文件夹显示“未缓存”占位（与漫画文件一致），点击可正常下钻浏览。
- [ ] 本地文件夹封面行为不回归（cover.jpg 优先、首页兜底、无漫画文件无封面）。
- [ ] `cargo test --lib` 与 `flutter analyze` 通过。
