# 应用内更新下载与安装交接优化

## Goal

让用户在更新弹窗中确认下载后，无需手动返回“设置 → 关于与更新”即可连续查看下载、失败重试和安装交接状态；完成下载后自动执行每个平台允许的安装启动动作。

## Confirmed Facts

- `UpdateManager` 已具备版本检查、镜像切换、文件大小校验、下载进度、Windows 安装器启动和 Android 系统安装器调用能力。[`update_manager.dart`](D:/Projects/RCH-source/app/lib/store/update_manager.dart:302)
- 更新弹窗点击“下载更新”后仅调用 `m.download()` 并关闭弹窗；进度和“立即安装”按钮位于设置页的 `UpdatePanel`。[`update_panel.dart`](D:/Projects/RCH-source/app/lib/ui/update_panel.dart:270)
- Android 当前通过现有 `rch/updater` 通道调用系统安装器；未知来源权限或系统确认失败时会恢复到可重试状态。

## Requirements

- **R1** 用户在更新提示中明确选择“下载更新”后，应用立即展示同一更新操作的可见进度，不要求用户手动导航到设置页。
- **R2** 同一安装包在下载期间只能有一个活动下载；重复触发必须复用当前状态或被明确拒绝，不能并发写入同一文件。
- **R3** 文件大小校验成功后，Windows 自动启动既有安装器；若用户取消 UAC 或启动失败，UI 恢复到可重试状态。
- **R4** Android 自动拉起系统安装确认界面；系统的未知来源授权和最终安装确认必须保留，失败时给出可操作提示且保留安装包。
- **R5** 用户选择“稍后”或尚未明确确认下载时，不下载、不安装、不改变现有静默检查语义。
- **R6** 下载镜像切换、失败信息和“打开 GitHub Releases”兜底保持可用。

## Acceptance Criteria

- [ ] 从更新弹窗选择下载后，在一个可见界面中立即看到进度、下载完成或失败状态；不需要用户再进入设置页寻找状态。
- [ ] Windows 成功下载且大小校验通过时，自动发起安装器；Android 成功下载时，自动发起系统安装确认而非宣称静默安装。
- [ ] 下载失败、镜像全部失败、用户拒绝系统权限或取消 UAC 时，应用不崩溃、不丢失可重试状态，并给出下一步动作。
- [ ] 自动化测试覆盖版本比较、候选安装包选择、重复下载保护和下载完成后的平台交接决策；平台通道用可替换接口或模拟验证。
- [ ] `flutter analyze` 和更新相关测试通过。

## Out of Scope

- 自动下载而不经用户确认、Android 静默安装、重写发布服务器或变更镜像协议。
- 在本任务中引入完整的更新签名体系或新的后台下载服务。
