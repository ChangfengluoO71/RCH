# 条漫快速翻页稳定性：技术设计

## 根因与目标状态

当前条漫把“导航意图页码”“滚动视口推导页码”和“异步测得的页面高度”都直接写入 `_page`。未知高度按 0 累加后执行滚动，旧动画/旧滚动回调便可覆盖最后一次导航；高度收敛时又会改变累计偏移。这也是页码卡住后回跳、阅读进度写错的直接原因。

改动后，最后一次有效导航是唯一权威意图；滚动和布局测量只提供观察值，不能覆盖仍在进行的导航意图。

## 状态模型

在 `reader_page.dart` 的条漫逻辑中引入独立的导航会话（可为私有控制器或纯状态模型）：

- `generation`：每次页进退或跳转递增；异步回调只在 generation 仍匹配时生效。
- `pendingTarget`：最后一次请求到达的目标页；用户主动拖动时取消它。
- `measuredHeights` + 非零估算高度：未知项不再按 0 参与偏移计算，估算值由已测条目/占位高度得出。
- `observedPage`：滚动中心推导出的页，仅在没有 pendingTarget 且滚动稳定后才可提交为当前页。

`_go`、页码跳转及条漫中的其他按页导航入口统一走一个 `requestWebtoonPage(target, animated)` 路径；不再各自直接修改 `_page`、滚动和写阅读记录。

## 导航与布局流程

```text
用户导航 -> 创建新 generation / 覆盖 pendingTarget
          -> 预取目标附近图片
          -> 使用已测高度 + 估算高度滚动到近似位置
图片或布局测高 -> 若仍是最新 generation，安排一次帧后校正
滚动稳定       -> 验证目标/中心页，提交页码并写入阅读进度
用户手势滚动   -> 取消 pendingTarget，稳定后以中心页更新页码和进度
```

- 旧动画、旧 `postFrameCallback` 和旧 `recordRead` 完成回调必须因 generation 不匹配而失效。
- 布局高度变化期间仅校正最新目标，不把 `_onWebtoonScroll` 的中间值写回旧页。
- 当目标页真实高度尚不可得时，保留目标页显示和导航会话，待测高后收敛；不以“禁用快速操作”规避问题。
- 阅读进度只在已提交的最终页或用户手势稳定后写入；页码跳转也必须走同一持久化路径。

## 测试设计

将“累计偏移、中心页映射、未知高度估算、generation 失效”抽成可在 Dart 单测中驱动的小型纯模型；widget 测试只验证其与 `ScrollController`、图片高度回调和标题/进度 UI 的整合。

必须覆盖：

1. 部分高度未知时连续请求 A、B、C，随后旧回调与高度收敛抵达，最终只接受 C。
2. 目标页由占位高度变为真实高度、AI 版本变化和重新进入条漫时，页码不倒退。
3. 用户手势打断导航后，中心页可正常接管；手势没有打断时，滚动回调不能接管。
4. 日漫/美漫、双页、缩放与既有按键行为不受条漫状态机影响。

## 兼容性与回滚

- 不修改 `BookInfo`、远程书源、图片解码或持久化数据格式。
- 只在 `ReadMode.webtoon` 启用该模型；其他模式沿用当前 `PageView` 路径。
- 若上线出现定位异常，可回滚该子任务提交，不会损坏已写入的阅读记录格式。
