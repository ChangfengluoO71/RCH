# 全云端远程扫描与封面索引

## Goal

为所有需要会话的云端书源建立统一的远程媒体扫描能力：首次授权或首次打开根目录后在应用进程内后台全量扫描，后续打开/授权执行可恢复的增量扫描，并提供手动增量重扫和全量重扫。扫描必须识别直接包含图片的远程文件夹漫画，生成可复用封面，接入现有 Reader、阅读后缓存清理和远程删除失效清理，同时不改变 M8 Catalog-only/local-only 边界。

## Scope

- 云端 provider：WebDAV、SFTP、百度网盘、115（扫码 Cookie 与现有兼容模式）和夸克。
- SMB/NAS 继续按本地文件系统处理；可复用图片文件夹分类，但不参与授权触发的云端扫描任务。
- Rust 负责 provider I/O、扫描状态、限速/并发、封面依赖和缓存一致性；Dart 负责触发、控制和展示。
- 保留现有压缩包阅读策略、Range 安全契约、凭据边界和 M8 线上 provider 排除项。

## Requirements

### R1 — 触发与生命周期

1. 会话首次建立成功，或会话存在时首次打开云端根目录，且来源从未完成扫描时，启动一个可恢复的全量扫描。
2. 同一来源重复打开、重复授权或多个页面同时请求时只能复用同一个 job。
3. 后续打开/授权启动增量扫描；应用重启、系统挂起或进程终止后从持久检查点继续。
4. 用户可显式执行增量重扫或全量重扫；全量重扫用于权威删除核对。
5. 扫描必须尊重全局开关：`remoteBackgroundScanEnabled` 控制自动任务，现有 `remoteCoverFetchEnabled` 控制远程封面网络请求。关闭封面请求时可继续更新索引，但不得发起封面 I/O。

### R2 — Provider 统一能力

1. 所有云端 provider 通过统一 adapter 暴露目录分页、元数据、路径归一化、有限文件读取和随机/Range 能力探测。
2. provider 能力与错误必须结构化表示，至少区分认证过期、权限拒绝、未找到、限流、临时网络错误、Range 不可用、响应格式错误和取消。
3. 不支持某项能力时必须明确降级，不得用错误字符串猜测、伪造成功或把一个 provider 的下载语义套到另一个 provider。

### R3 — 清单与增量

1. 权威远程清单保存在 Rust 数据库；现有 JSON 快照仅作 UI 短期缓存。
2. 保存 `size/mtime`（若 provider 提供）、规范化子清单哈希、generation、分页完整标志和检查点。
3. 增量扫描只递归新增、删除、未完成或指纹变化的目录；缺少可靠 mtime 时使用子清单哈希/短 TTL，不能把空列表当作删除。
4. 每个目录只有在所有分页成功后才可提交 `listing_complete` 和缺失项 tombstone；部分/失败响应保留旧清单。
5. 图片子项变化必须使所属图片文件夹漫画和容器封面依赖失效并重新排队。

### R4 — 资产识别与封面

1. 支持 archive file、image file、image folder、container directory、plain directory/other file 五类资产。
2. 直接含 jpg/jpeg/png/webp/gif/bmp/avif 的目录识别为可阅读的图片文件夹漫画；忽略隐藏和系统目录，按自然排序确定页序和首图封面。
3. 每个压缩包和图片文件夹都进入封面任务；容器目录从确定性排序后的第一个已识别子漫画获取封面。
4. 封面任务优先使用已验证的局部 Range/随机读取；Range 不可用时沿用占位符和提示，不自动整本下载。图片文件夹只读取单张图片，受单文件大小上限约束。
5. 封面缓存以稳定逻辑书籍键、封面参数和内容指纹寻址，不能依赖 raw 临时路径；记录封面实际依赖路径。

### R5 — 调度与资源上限

1. 扫描队列必须低于前台当前页和 Reader 预取，使用共享请求预算、provider 限速、全局/单来源并发上限和有界队列。
2. 同一来源、路径、内容指纹和封面参数的可见请求与后台任务必须合并，不得重复下载。
3. 列表批次、封面响应、图片页和内部缓冲必须有上限；不能出现随目录/文件大小线性增长的常驻内存。
4. 暂停阻止新任务；取消清理未提交结果并保留检查点；已开始的 I/O 完成后不得回写已取消 job 的成功状态。
5. 429/5xx/断线使用有界退避并遵循 `Retry-After`；认证失败、权限拒绝和 Range 不可用不得产生重试风暴。

### R6 — 图片文件夹 Reader

1. 图片文件夹通过现有 `Document`/Reader 打开，页数、自然排序、当前页记录和预取语义与压缩包一致。
2. 每页独立读取；Range 可用时使用随机读取，Range 不可用时只允许受上限约束的单图片响应，不生成整本 raw。
3. 使用现有逻辑 `BookKey`、Reader governor、L1/page cache 和阅读完成清理，不能创建第二套阅读生命周期。
4. 压缩包仍遵守原有 `stream/download/auto` 与 Range 降级契约，不因扫描功能改变。

### R7 — 缓存与远程删除

1. 阅读完成只删除 page/raw 内容缓存，保留封面、元数据、书源、凭据、标签、历史、完成状态和自定义封面参数。
2. 只有经过完整且成功目录校验产生的 tombstone 才可清理漫画封面、别名、依赖图片缓存和 page/raw；容器删除需递归处理已索引子项。
3. 认证失败、权限错误、断线、截断列表、取消或单文件暂时 404 均不得判定远程删除。
4. 清理失效漫画时必须同时处理由图片子项生成的封面依赖；不影响未关联路径。

### R8 — UI、设置与安全

1. 来源页显示排队、扫描中、已完成、Range 不可用、失败和暂停状态，并提供继续、重试、增量重扫和全量重扫。
2. 卡片优先读取本地已生成封面；可见卡片按需请求必须与后台 job 去重，失败显示可解释占位符而不阻塞阅读。
3. 日志、统计、测试产物和报告不得出现 Authorization、Cookie、token、密码或带凭据直链；路径可使用哈希/脱敏值。
4. 应用级后台 worker 不新增常驻 Android Service/WorkManager；系统挂起/进程终止依靠检查点恢复。
5. 增加全局 kill switch，可立即回退到现有按需封面行为且不删除已生成的清单/封面。

### R9 — M8 与版本边界

1. 本任务不得调用 M8 线上智能刮削或新增元数据 provider；线上刮削继续作为未来插件。
2. 不升级 AGP、Gradle、Kotlin、NDK 或 provider API 版本；不改变应用版本号、tag、release 或用户已有 dirty 文件。

## Acceptance Criteria

- [ ] 五类云端 provider 均通过统一 adapter contract fake，覆盖分页、缺失 mtime、206、200、416、坏 Content-Range、429、403、认证失效、截断列表、删除目录和嵌套图片文件夹。
- [ ] 首次授权/首次打开只产生一次全量 job；重启/中断可续跑；后续打开为增量；手动增量和全量重扫可区分并可观测。
- [ ] 目录/文件清单、资产类型、内容指纹、封面依赖和扫描状态可从数据库复核，旧 v1 快照迁移不造成空库或误删。
- [ ] 压缩包与直接图片文件夹均能生成封面；Range 不可用时不触发整本下载，状态和提示正确。
- [ ] 前台阅读请求始终优先于预取和扫描；队列有界、同键去重、取消/恢复正确，内存不会随整本大小线性增长。
- [ ] 图片文件夹可逐页 Reader 打开；阅读完成清理保留封面和所有关键元数据/设置/历史/自定义封面参数。
- [ ] 只有完整成功远程刷新后的 tombstone 才清理失效封面/别名/依赖缓存；失败或部分刷新不清理。
- [ ] `remoteBackgroundScanEnabled` 与 `remoteCoverFetchEnabled` 的关闭/开启语义有回归测试；kill switch 可回退旧行为。
- [ ] Rust、Flutter、Windows 构建与测试命令按项目门禁执行；真实 provider/设备证据缺失时明确标记 pending，不伪造 GREEN。

## Non-goals

- M8 线上智能刮削、第三方元数据 provider 和插件系统实现。
- 远程云盘整库下载、常驻系统后台服务或改变现有压缩包下载策略。
- SMB/NAS 授权扫描流程；SMB 只复用本地图片文件夹识别。
- 删除或重写历史任务、用户已有工作区变更、凭据迁移策略。

## Dependencies and ordering

1. `remote-scan-manifest` 先定义 schema、adapter contract、指纹和 tombstone 语义。
2. `remote-scan-worker` 依赖 manifest，提供共享调度、封面批处理和检查点。
3. `remote-folder-reader` 依赖 manifest 的图片文件夹清单和 worker 的 provider 读取能力。
4. `remote-cover-cleanup` 与 reader 并行实现，但必须在 manifest 的依赖键稳定后接入。
5. `remote-scan-ui-verify` 在上述接口稳定后接入 UI、设置、fake contract 和真实验证。
