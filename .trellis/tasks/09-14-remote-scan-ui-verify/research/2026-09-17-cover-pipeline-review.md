# 云端扫描、目录封面与请求调度长期方案评估

日期：2026-09-17。范围：代码审计、公开资料调研和建议；未修改生产代码，未发起真实账号压力测试。

## 结论

推荐在现有 Rust 清单、封面依赖和请求治理器之上，逐步统一目录展示查询与封面服务。Flutter 负责展示和提交需求，Rust 负责索引、任务、网络预算和缓存。保留 provider 适配层，不重写整个书源系统。

当前问题核心是后台索引、浏览快照、可见封面请求三个流程尚未共享完整的数据契约。单纯增加转圈、提高并发或补一次终态刷新不能闭环。

## 对上一轮结论的修正

- `RCH.exe` 修改时间为 2026-09-16 20:13:29，但同目录 `rust_lib_app.dll` 为 2026-09-17 10:18:47。exe 时间戳不能证明 Rust 或 Dart 业务代码陈旧。需要实际加载模块、构建标识与 Dart/Rust 版本证明；不能把旧构建作为已确认原因。
- 115 cid/pickcode 的区分解释如何定位资源，不要求用户手动进入目录。后台列目录也能取得文件 pickcode。
- 官方开放平台与扫码 Cookie 非官方接口不同。open.115.com 可访问但本次未取得可读接口正文，官方语雀下载接口页面也未能读取。OpenList SDK 和 115driver 是维护者一手实现资料，不是 115 官方保证。
- HTTP 405 的标准语义是方法不允许；HTML 405 可以与网关拦截有关，但不足以证明请求雪崩，也不足以证明缺少时间戳。必须区分列表、取链、CDN Range 等阶段。

## 方案比较

1. 仅修改状态文字、增加动画和终态刷新：成本低，适合止住误导；无法解决容器目录取不到代表漫画、重复提取、重启恢复和错误吞并。
2. UI 给每个文件夹递归列目录：能较快看到封面，但网络量依赖滚动与组件重建，和后台扫描重复，难以控制 115 风险。仅允许提交统一队列中的按需目录发现任务，不在卡片内自行递归。
3. 统一清单展示查询、封面服务与持久任务队列：推荐。复用现有 SQLite、provider adapter、reader governor 和删除证明；增量迁移，保持 FRB 兼容入口。
4. 全部走网盘自带缩略图：可作能力增强。图片可能有可用缩略图，压缩包/图片文件夹的漫画封面语义未获保证，不能覆盖自定义页码和裁剪，也不能成为核心依赖。

## 推荐设计

### 1. 统一目录展示查询

新增逻辑上的目录展示查询，一次返回可见条目的资产身份、目录类别、代表漫画 ID、封面版本与状态。

- 图片文件夹：以已验证分页完整的图片清单和自然序选择首页。
- 容器目录：从扫描索引选自然序代表漫画，不依赖浏览快照。
- 只有子目录的目录：按稳定规则选择后代代表封面；限制查找预算，后台补全。
- 用户自定义封面优先；已有可用封面保持显示，新结果完成后再切换。
- 用 sourceId + provider 稳定 ID（无稳定 ID 时使用规范路径）表达资产身份；保留父子关系。cid、pickcode、路径和临时直链分开存储。
- 快照仅保留为迁移兼容/离线辅助，不作为删除证据。

### 2. 封面服务与分层缓存

可见卡片、后台任务和自定义封面操作进入同一个服务。同一本同一内容版本同一封面选择只提取一次。

- 先读内存和磁盘，网络开关仅约束缓存未命中后的远程 I/O。
- 缓存身份包含 source、asset、内容版本、选择页、裁剪及渲染规格；不同画质从已缓存的合适源图派生，不能把低清放大冒充高清。
- 保留压缩后的封面源图（受大小限制）和少量派生缩略图，避免每种尺寸都重新访问漫画。
- 默认后台预览不能覆盖用户选页/裁剪；预览与用户选择分别标记版本和用途。
- 文件原子发布后再标记 ready。恢复时核对文件存在/完整性，事件丢失也能从数据库重建。
- 旧缓存以兼容读取、按需迁移方式接入，避免升级触发全量重新取封面。

### 3. 列目录和封面任务分离

两条持久任务队列共享网络预算，目录发现后可逐步安排封面。先采用已发布清单内的逐项更新；后续再实现完整目录批次的提前预览。

提前预览不得放宽现有删除保护：新增/更新的预览可见，不代表整棵树扫描成功。删除、tombstone 和失效清理仍要求当前 source/root/session/generation 的完整证明。残缺分页、失败或取消保留旧数据。

任务记录 pending/running/ready/retry_wait/blocked/unsupported/failed，携带重试次数、下次时间、generation、租约。重启回收失效租约，继续未完成任务。失败封面队列不依赖下次增量能否重新遍历到该目录。

目录完整基线和封面就绪率独立：目录可完整而有封面等待重试。UI 应明确呈现“目录扫描完成，封面仍在处理”，不能把所有占位当作完全成功。

### 4. 请求治理与 115

- 保留总并发上限和前台阅读保障；限额聚合到 provider/账号级，避免同一账号多个根目录各自限流后叠加。
- 按账号身份、认证代际和 pickcode 合并同一取链请求；不同文件仍受总预算限制。按键合并不等于放开并发。
- 可见封面优先于后台封面；阅读当前页优先。预算等待应可取消，退避期间释放工作槽，避免占着全局槽等待账号锁。
- 缓存直链及探测结果时绑定认证/内容/URL 有效期；失效后单次受控刷新。UA 与取链契约保持一致，真实线上的空 UA 与省略 UA 差异需要验证。
- 保留 typed errors：登录失效、权限、疑似拦截、限流、超时、截断、Range 不支持、解码失败和本地存储错误。
- WAF/限流暂停对应范围的后台请求，用一次恢复探测控制恢复；指数退避加随机扰动、总重试预算；不让全部封面在冷却结束同时重试。
- Range 只在有有效协议证据时记“不支持”；错误结果不得永久污染能力缓存。
- 不给出未经真实账号验证的“安全 QPS”。先记录各阶段延迟与请求量，再保守调整。

### 5. 进度、设置和清理契约

中文示例：目录“已检查 38 个目录，已发现 273 本，仍在发现”；封面“可用 210、处理中 1、待处理 48、待重试 12、不支持 2”。目录发现结束后才显示固定总数/百分比。

仅 running 项转圈，pending 显示等待，冷却显示稍后重试，有旧封面则继续显示旧图。计数来源于任务状态；重试不增加漫画总数。图片文件夹算一本，容器目录不重复计一本。

任务结果批量通知 Flutter，按资产 ID 定点更新。可先用单一增量轮询入口，后续接 FRB 事件流；事件序号断档时重读快照。批量 setState、稳定 key、去重目录查询，单独验证 AXTree 问题。

- 关闭自动扫描：停止自动发现与后台补封面；手动操作仍遵守封面网络总开关。
- 关闭封面网络：保留并读取全部已有封面，阻止新的自动/可见封面网络任务；运行任务在下个 I/O 边界检查。
- 阅读后清理：仅 page/raw/content，保留封面、选择参数和关键记录。
- 清理已验证失效漫画：移除对应封面依赖；被其他活目录引用的共享图按引用关系处理，目录重新选择代表封面。
- 删除后的迟到 worker 不能重建已删除缓存，写入前复核当前 generation、内容版本和 tombstone。
- 缺少可信递归变更标记时，增量仍需周期性遍历目录元数据，仅对变更内容重取封面；父目录 fingerprint 相同不能证明所有后代未变。

## 分阶段落地与验证

1. 修复证据与语义：构建标识、保留真实错误、分离处理/成功计数、读磁盘不受网络禁用影响。验证 405 不再显示成 Range 不支持。
2. 完成最直接闭环：容器代表漫画从 SQLite 查询、逐项封面更新、统一键和缓存入口。首次停留根目录不点击子目录，也能出现图片文件夹与压缩包容器的封面。
3. 持久队列和账号预算：单任务合并、可见优先、冷却/重试、重启恢复和深层增量补查。不得仅提高线程数量。
4. 优化首屏：在保留删除证明的前提下逐目录生成预览；评估 provider 原生缩略图、Range 合并和画质派生收益。

验收覆盖：冷启动根目录；200+ 文件混合目录；后台与可见请求撞同一本；405/401/429/超时/截断；运行时关闭开关；更改画质/页码/裁剪；重启；书源改根；阅读后清理；远端深层新增/删除；分页中断；清理与迟到结果竞态。记录请求数、取链去重率、缓存命中率、首屏封面时间、阅读页 P95 延迟和按原因划分的失败数。真实账号结果仍需实测，当前审计不宣称问题已经修复。
