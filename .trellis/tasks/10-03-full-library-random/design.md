# 全库随机阅读设计

## 现状与决定

当前两个随机入口把 `LibraryStore.recent` 交给选择器，因此未读漫画永远不会入池；首页还把筛选后的列表传给选择器。`library_index` 已统一保存本地和远程条目，但普通目录、漫画图片目录与归档漫画还没有统一的本地可抽选标记。

本设计以 `library_index` 为随机数据源，通过 Rust SQLite API 返回小批候选；Flutter 层只解析来源、校验本地路径并应用最近选择策略。远程候选只取已提交的完整目录清单中的归档文件和已完成图片目录。

## 数据范围与索引

- 候选查询只连接 `book_sources.deleted = 0 AND remote_only = 0` 的本机书源；不取仅有同步元数据、无法在本机打开的幽灵来源。
- 本地与 SMB 归档依据索引器已支持的漫画扩展名；目录依据新增/统一的 `asset_kind` 标记。索引扫描时按直接子项分类：含归档漫画为 `ContainerDir`，否则含直接图片页为 `ImageFolder`，其余为普通目录。图片扩展名和隐藏文件排除规则沿用 FolderBook。
- 远程归档要求其父目录在 `remote_listing_state` 中有 `listing_complete = 1` 的已发布清单。远程 `ImageFolder` 同时要求自身清单完整，保证现有阅读入口会以图片目录方式打开它。staging 表中的临时条目不参与候选查询。
- 给基础 `library_index` 增加可空 `asset_kind` 列，使用加法迁移兼容旧库；旧目录缺分类时，在下一次索引刷新中补齐。Dart/Rust 索引 DTO 保留该字段，确保加载、持久化和远程扫描数据不会相互覆盖。
- 数据库查询只做 SQL，不在数据库锁内访问文件系统。查询返回候选后，Dart 异步检查本地文件/目录是否存在；失效路径只对本次选择排除。

## 候选 API 与随机策略

- 在 Rust library API 增加随机候选查询，参数为排除的漫画键、临时失效候选键和批量上限，返回 `source_id`、`source_type`、`path`、`title`。
- SQL 过滤已删除条目、幽灵来源、非漫画文件/目录及未完整发布的远程条目；按规范漫画键去重后随机排序，返回最多 32 条。批次为空时，Flutter 继续放宽最旧的历史项或跳过已失效项，避免将有效候选永久锁死在短历史池中。
- 选择记录全局保存最近 10 个漫画键。读取历史不改变阅读进度。选择后立即记入历史，避免失败漫画被连续重复抽到。
- 首页、阅读结束弹窗和阅读器顶栏共用一个 selector。首页传入查询/标签只用于展示，随机选择直接访问全库 API；阅读器入口额外排除当前漫画键，并关闭当前 reader 后打开选择结果。
- 阅读器顶栏入口不依赖当前页面/模式状态，因此漫画载入中、载入失败及单页/双页/条漫模式下均保持可见；忙碌时禁用重复选择。

## 备选方案与取舍

1. 继续从阅读记录随机：实现成本最低，但不可能选中未读漫画，无法满足全库范围。
2. Dart 分页加载所有书源后在客户端蓄水池抽样：不需新随机查询，但每次点击要扫描大量索引并传输所有候选，且本地文件夹仍需分类。
3. 本设计的索引分类 + Rust SQL 随机批次：候选筛选留在权威索引层，单次只传少量 DTO，本地 I/O 位于 SQLite 锁之外；额外工作是给本地索引补分类并生成 FRB 绑定。

选择第 3 项，以保证全库覆盖、不会在点击时联网、并限制每次调用的数据量。

## 错误与兼容

- 如果书源当前索引为空，界面显示“没有可随机阅读的漫画”，不隐式回退到阅读历史。
- 某个本地路径已删除时跳过该候选继续取样；远程网络或凭据错误由阅读器打开错误恢复界面处理。
- 已有旧设置中的随机历史继续读取；缺失字段视为空列表。最近历史上限固定为 10。
