# 添加书源耗时优化与加载反馈

## Goal

缩短添加书源的等待时间，并在等待期间明确显示操作正在进行。

## Background

用户反馈手机端点击“添加”后约需等待 8 秒才完成，期间缺少进度反馈。

## Requirements

- 检查添加书源从点击“添加”到完成的耗时，优化可避免的等待。
- 操作未完成时显示等待转圈；成功或失败后结束等待状态。
- 失败时保留可理解的错误反馈，避免等待状态卡住。

## Acceptance Criteria

- [x] 点击添加后立即看到等待转圈，转圈持续到成功或失败。
- [x] 成功和失败路径都会正确结束等待状态，失败信息仍可见。
- [ ] 在代表性手机环境下测量并记录优化前后耗时；消除已确认可避免的延迟。

实现记录：SQLite 迁移完成后只等待新增书源行写入和书源树刷新，完整 JSON 备份排入后台；保留迁移未完成时的旧保存路径。运行时 debug 日志记录迁移检查、书源写入、目录刷新和总耗时。手机实测仍待用户环境验证。

## Deferred Details

- 具体耗时目标在定位主要耗时来源后确定。

## Notes

- 当前需求来自用户对手机端添加书源体验的反馈。
- 相关现有入口位于 `app/lib/ui/home_page.dart` 的书源提交流程。
- 补充现场信息：耗时发生在添加本地图片文件夹书源，用户退出并重启后才看到书源。该路径不做云端连接校验；重点检查持久化和书源树刷新。
