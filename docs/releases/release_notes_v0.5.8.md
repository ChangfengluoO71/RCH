# RCH v0.5.8

本版重点是**打开速度**与**封面管线**：把"打开一本书要读多少远端数据"从"整本/整目录"降到"只读需要的几百字节"，并把此前长期失败的封面链路逐层修通。

## Improved

### 打开更快（惰性按需读 + 缓存复用）

- **EPUB**：打开只读中央目录，章节内容按需解析 —— 真机 **30.8 s → 0.59 s**。
- **ZIP / CBZ**：打开只读中央目录，打开成本与页数无关；封面走快速通道。
- **MOBI**：打开只读 PalmDB 头 + 记录表 + 每条候选记录的 16 B 魔数；封面只探测到第一张图。
  - 完整打开的逐条魔数探测改为**并发取**（瓶颈是 RTT：实测每次 136–182 ms、只取约 29 字节）。
  - 新增**页表缓存**：同一本书第二次打开**零探测**（实测远端读 **45 → 5 次**，约 9 倍；按真机 RTT 估算 300 页的书 ~41 s → ~0.7 s）。
- **PDF**：惰性按需读（真机打开 1.0–1.6 s，仅 12–18 次读）；封面按显示尺寸渲染。
- **读取合并（G1）**：钉住文件头窗口 + 元数据窗口槽 2 → 4 —— 真机同一 `offset=0` 曾被反复重取 108–135 次、一次 EPUB 会话里 906/1265 次小读吃掉 62% 的读时长，现已在源头消掉。
- **默认流式阅读**：`auto` = 流式优先，失败转整本下载（并有"阅读完成后自动删除整包"可选）。

### 封面

- 修复 **Release 版缺 `pdfium.dll`** 导致 PDF 打不开/封面失败（该 dll 现已纳入安装产物）。
- 已有字节时走**纯只读回退**：不再因为"没有 durable 行"就显示占位。
- **失败封面可重试**：源浏览器「刷新」会同时把该源当前档的终态失败封面重新排队（不动其它档、不清缓存）；并修复了"任务排回 pending 却没人抓"的会话顺序问题。
- 无稳定 asset id 的卡片（容器文件夹漫画）现在也会订阅封面 revision —— 修复"**详情页出图后海报墙不刷新**"。
- unified 缓存没有字节时回退 **legacy 纯本地缓存**（零网络）—— 修复"**详情页有封面、海报墙显示获取失败**"。
- **取消"故意整本读"的字节预算拒绝**（保留 384 次读 / 30 s 两条继续兜住病态归档）；MOBI 惰性打开对越界偏移、空区间记录改为**跳过**而不是整条弃权。
- 修复 `cover_native_lib_missing` **误标**：pdfium 的库内错误不再被当成"部署缺原生库"。
- 真机结果：长期失败的一批夸克 MOBI 封面全部就绪（源级 **可用 63 → 284**、失败 13+ → 1、待处理 0）；一本 82.6 MB 的 MOBI 封面 **719 ms 打开、198 ms 出图**。

### 缓存治理

- `cache/raw`（整本下载包）新增 **2 GiB 容量上限 + 最旧优先整包淘汰**（始终保留最新的包），配合既有的"阅读完成后自动删除整包"与手动清空。
- 页缓存**按渲染宽度分目录**：换档不误用旧尺寸，也不作废标准档已有缓存。

### 界面与交互

- 新增 **「阅读渲染宽度」** 设置：省流 1080 / 标准 1600 / 跟随屏幕（标准档与历史行为完全一致）。阅读页每页交给界面的数据量从约 1.9 MB 起可显著下降。
- **115 / 夸克「原文件名」不再显示 provider id**（32 位 hex、19 位数字 id 均回退为目录项名称）。
- 扫描状态栏简化：移除「暂停/继续、增量重扫、全量重扫」三个按钮（扫描自动运行），保留「重试远程扫描」。
- 设置项按类别折叠；二维码保存修复；对比度与文案修正。

### 可排障性

- 新增 `pdf_diag.log` / `reader_diag.log` / `mobi_diag.log` 现场诊断；封面读取预算失败会自证"哪一条先超"（字节/次数/时间）；MOBI 惰性打开的**拒绝原因**落盘，不再需要猜。

## Verification

- Rust 全量门禁（`cargo test --locked --no-fail-fast`）：**25 个测试套件 / 544 项通过 / 0 失败**。
  - 新增契约包括：MOBI 页表缓存命中/失效、惰性打开对零长度与越界记录的容忍、文件头窗口"回到头部零新增请求"、封面的"无 asset id 也订阅 revision"、"unified 失败回退 legacy"、"故意整本读豁免预算但超 512 MiB 仍拒"、`cache/raw` 上限淘汰、缺库误标的回归。
  - 关键回归均做过"**验证测试本身**"：临时回退实现时用例确实失败（例：回到文件头 `before=5 after=6`；库内错误被标成 `cover_native_lib_missing`）。
- Flutter：封面相关 12 个文件 49 项、设置/详情/仓库等多项测试通过；`flutter analyze` 干净。
- 真机复验（Android 与 Windows Release）：封面就绪 **284** / 失败 **1** / 待处理 **0**；MOBI 第二次打开 `mode=lazy-cached cache=hit`；G1 的 A/B（项目自带 P0 仪器）请求数 8 vs 8–9、无读放大回归。
- 已知 flake（与本次改动无关，已在 LOG 记录）：`p0a_single_page_latency_without_background_load` 是**下限**断言（要求至少一页 ≥500 ms），机器空闲时可能失败。

- ⚠️ **签名提示**：CI 发布包使用仓库内的正式签名；若你手机上装的是**本地 debug 签名**的测试包，安装正式包前需要先卸载（会清空应用数据）；想保留数据就继续用本地构建的测试包。
